Method · AI-led engineering

I don't type the code. I decide what must stay true, and prove it does.

Eight steps for every change. The cheapest capable model does each task, and a model from another vendor reviews it.

  1. Clarify

    Scope, risk tier, limits.

  2. Write the rules

    Promises become numbered rules.

  3. Plan

    A lead model routes the work.

  4. Build

    Helper agents implement.

  5. Pin with tests

    Every rule gets a named test.

  6. Attack

    A rival model tries to break it.

  7. Mutate

    Seeded bugs prove the tests work.

  8. Gate & ship

    CI checks everything, then deploys.

I own the judgment: rules, risk tiers, quality targets and decisions. The AI does the labor, and all of it can be audited.

It's the same job as leading people: set standards, review, measure, write it down.

review / users / session-revocation.md● Accepted · May 2026

Closing the gap after a session is revoked

Problem
When a user signed out a session from another device, its access token kept working for up to an hour, until it expired on its own.
Options
A denylist in the cacheCheck every request against a list of revoked tokens. It works, but it adds a cache lookup to every call and a new thing that can fail.
A token version on the user ✓Stamp a version number into each token and bump it on any revoke. Stale tokens are rejected by the check that already runs on every request.
Decision
Use the token version. With the existing 5-second user cache, a revoke takes effect within seconds instead of an hour, with no new infrastructure.
Related
In the same round: mandatory 2FA extended to content-editor roles, because they can publish site-wide and carry the same risk as moderators.
Proof
Pinned as invariant USR-014. Its test issues a token, bumps the version, waits past the cache window and checks that the token is refused.
